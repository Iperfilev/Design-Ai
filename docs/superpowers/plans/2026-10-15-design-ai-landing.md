# Design + AI Landing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать адаптивный лендинг IT STEP с точным содержанием исходной страницы и оформлением выбранного оранжевого варианта №3.

**Architecture:** Одностраничный frontend без серверной обработки. Исходные тексты и ссылки хранятся отдельно от шаблонов; семантическая разметка работает с прогрессивным улучшением JavaScript. Брендовые SVG используются без изменений, графика — отдельными оптимизированными файлами.

**Tech Stack:** HTML5, CSS, JavaScript ES modules; Node.js built-in test runner для содержательных автоматических проверок.

**Spec:** `docs/superpowers/specs/2026-10-15-design-ai-landing-design.md` — согласовано пользователем 15 октября 2026.

## Global Constraints

- Основной сценарий — просмотр с телефона; аудитория 18–55 лет.
- Визуальный ориентир: https://design-ai-visual-directions.grassycabin1024.chatgpt.site/concept-3.png
- Источник содержания: https://almaty.itstep.org/graphic-design-ai
- Срок — 12 месяцев.
- Сначала ШАГ, справа Astana Hub; оригинальные предоставленные SVG.
- Графитовый фон, белая типографика, оранжевые акценты, дизайнерские постеры и объёмная графика.
- Не заменять исходные тексты слоганами из сгенерированных картинок.
- Сокращения и редакционные изменения исходного текста требуют отдельного согласования.
- Отправку заявок, CRM и обработку персональных данных сейчас не подключать.
- Не подключать оплату и не имитировать её успешное выполнение.
- Проверить ширины 360, 390, 768 и 1440 пикселей.
- Основной текст от 16 пикселей; кликабельные элементы не менее 44×44 пикселей.
- Учитывать prefers-reduced-motion.
- Рабочая ветка: codex/design-ai-landing; не сливать в main без завершения проверки.
- Открытую галерею вариантов не заменять готовым лендингом без согласования публикации.
- Браузерную проверку нельзя подменять успешными статическими проверками.

## Review Focus

- Длинные исходные формулировки и увеличение шрифта не должны обрезать текст или создавать горизонтальную прокрутку — задача 2.
- Повторяющиеся ссылки и блоки исходного сайта не должны приводить к потере уникального содержания — задача 1.
- Кнопка заявки не должна отправлять данные или создавать ложное сообщение об успехе — задача 3.
- Управление только клавиатурой и переход по якорю при открытом меню должны работать без перекрытий — задача 3.
- Недоступные оригиналы студенческих работ не должны заменяться сгенерированными работами с ложным авторством — задачи 1 и 2.

## Файлы и ответственность

- `index.html`: семантическая структура страницы, metadata, доступная навигация.
- `src/content.js`: сверенные тексты, модули, контакты и ссылки.
- `src/render.js`: `renderCourseContent(root, content)`, формирование содержательных разделов.
- `src/main.js`: `initNavigation(root)`, взаимодействия меню и якорей.
- `styles/site.css`: адаптивная сетка, типографика, состояния, reduced motion.
- `assets/brand/`: оригинальные SVG.
- `assets/images/`: оптимизированные изображения с разделением реальных работ и декоративной графики.
- `docs/content-source.md`: дата сверки, карта источников, неоднозначные и недоступные элементы.
- `tests/content.test.mjs`: проверка полноты подтверждённых данных.
- `tests/page.test.mjs`: проверка семантики, ссылок и отсутствия неподключённой отправки.
- `package.json`: `test` для Node.js test runner; без обязательных runtime-зависимостей.
- `design-qa.md`: результаты визуальной и функциональной проверки, включая ограничения.
- `README.md`: запуск, структура, изменение данных и статус проверки.
